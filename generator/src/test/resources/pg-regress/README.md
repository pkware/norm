# PostgreSQL regression SQL

The grammar sweep (`RegressSweepTest`) parses every statement of the `src/test/regress/sql/*.sql` files of the latest
PostgreSQL 16 and 17 releases with the bundled libpg_query.

| Directory | Tag | Commit |
|-----------|-----|--------|
| `16/` | `REL_16_15` | `7d3e000c5961a544302072058a1184e9a588837b` |
| `17/` | `REL_17_11` | `083ac033419f690758508e08c1736089384bbee8` |

The files come from <https://github.com/postgres/postgres> and keep their PostgreSQL License, in `COPYRIGHT`.
`<major>/expected/` holds only the `src/test/regress/expected/*.out` files that `reject-list.txt` cites.

## How a file is read

- A line whose first non-blank character is `\` is dropped, except a line that starts with `\g`, `\gx`, `\gset`,
  `\gexec` or `\gdesc`. psql sends the query buffer at those, so the line becomes a line holding only `;`.
- The data of a `COPY ... FROM STDIN` statement is dropped through its `\.` line. libpg_query's parser decides which
  statements are such a `COPY`. The same holds for a `\copy` line whose text after the `\` parses as one, and for each
  part of a statement chained with `\;`, where the parts take data blocks in order.
- The lines of an inactive branch of a psql `\if` block are dropped, because psql never sends them. A branch is
  active by psql's boolean literals. A condition that psql evaluates and that is not a literal, such as `:skip_test`,
  makes its branch inactive, as psql does after an invalid value. Each such condition is logged as `P5`.
- `LibPgQuery.split` splits the rest. When the lexer rejects the text, the statement around the error is dropped, from
  the line after the last `;`-ending line before the error through the first `;`-ending line at or after it, and the
  remainder is split again. Each dropped statement is a reject-list entry.
- When a statement fails to parse and holds the keyword `ATOMIC`, the region grows one statement at a time until
  `pg_query_split_with_parser` accepts it and every statement it returns parses.
- A statement with a `:` next to a name or string, or with a `\`, is skipped and listed in `sweep-skips.txt`.

## Files

- `sweep-skips.txt` is generated by `./gradlew :generator:generateScannerBaseline` and compared byte for byte by the
  sweep test. Do not edit it.
- `reject-list.txt` is edited by hand. Each line names a statement that PostgreSQL rejects: file, statement ordinal,
  first line, and the `expected/<file>.out:<line>` of the error. The first line is the first line of the statement that
  is neither blank nor a `--` comment. The cited line starts with `ERROR:`, and that first line occurs earlier in the
  file with no other `ERROR:` line and no echo of the next statement's first line in between.
